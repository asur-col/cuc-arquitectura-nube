La pregunta de siempre: ¿el dato llega como archivo o como bloque?

NAS vs SAN: archivo o bloque

NAS — Network Attached Storage SAN — Storage Area Network
Entrega Archivos en carpetas compartidas Bloques — el servidor ve un disco "crudo"
Protocolos NFS · SMB/CIFS Fibre Channel · iSCSI
Red La LAN Ethernet de siempre Red dedicada de alto rendimiento
Quién manda en el filesystem El propio NAS El sistema operativo del servidor
Típico para Compartir archivos entre equipos Bases de datos, VMs, baja latencia
Truco para recordar: el NAS es un file server; la SAN aparece como disco local que puedes particionar y formatear.

LUN: la porción lógica que recibe cada servidor

LUN = Logical Unit Number — identificador SCSI de una porción del array
No es un disco físico — es una rebanada lógica del pool
Se presenta por FC / iSCSI — el host la ve como bloque crudo
Idea clave: la SAN reparte su capacidad en LUNs, una por servidor o aplicación.

RAID: velocidad y redundancia entre discos

RAID 0

striping

Máxima velocidad
Si falla 1 disco, se pierde todo

RAID 1

mirroring

Copia exacta en 2 discos
Usas solo el 50%

RAID 5

paridad distribuida

Mín. 3 discos
Tolera la falla de 1

RAID 10

espejo + stripe

Rápido y redundante
Mín. 4 discos, 50% útil

RAID agrupa discos físicos para ganar velocidad, redundancia o ambas — es la base del pool de cualquier array NAS o SAN.

Un dato, tres formas de guardarlo

Objetos

Archivo completo + metadatos
Acceso: API HTTP

Bloques

Disco virtual en bloques fijos
Acceso: montado en una VM

Archivos

Jerarquía de carpetas
Acceso: NFS / SMB compartido

La elección depende del patrón de acceso de la aplicación — no de la preferencia

Almacenamiento de objetos

Contenido estático — imágenes, video, sitios web
Backups y archivado — copias que se leen poco
Datos no estructurados — grandes volúmenes, data lakes
Escala prácticamente ilimitada: se accede por web, no se monta como disco.

Almacenamiento de bloques

Bases de datos — lecturas/escrituras intensivas
Sistemas operativos — discos de arranque de VMs
Baja latencia — acceso aleatorio de alto IOPS
Es la LUN de siempre, como servicio: un disco virtual dedicado a una sola instancia.

Almacenamiento de archivos

Contenido compartido — varias apps leen la misma carpeta
Protocolos estándar — NFS y SMB, como en casa
Lift-and-shift — migrar apps sin reescribirlas
Es el NAS como servicio: una sola jerarquía montada por muchos servidores a la vez.

Objetos Bloques Archivos

Se accede por API HTTP (REST), vía web Disco montado en una VM NFS / SMB, varios servidores a la vez
Latencia Mayor (llamadas web) Muy baja — sub-milisegundo Baja — milisegundos
Ideal para Contenido estático, backups, datos no estructurados Bases de datos, sistemas operativos Compartir contenido entre aplicaciones

Del datacenter a la nube: mismo concepto, nuevo formato

SAN · LUN

bloques por red dedicada

Bloques: Amazon EBS · Azure Managed Disks · Persistent Disk · OCI Block Volume
NAS

archivos por Ethernet

Archivos: Amazon EFS · Azure Files · Filestore · OCI File Storage
Sin equivalente

no existía on-premise

Objetos: Amazon S3 · Azure Blob · Cloud Storage · OCI Object Storage — nativo de la nube
La nube no inventó todo: bloques y archivos son SAN y NAS como servicio — los objetos sí son un modelo nuevo.

Mismo concepto, distinto nombre

Objetos Amazon S3 Azure Blob Storage Cloud Storage OCI Object Storage
Bloques Amazon EBS Azure Managed Disks Persistent Disk OCI Block Volume
Archivos Amazon EFS Azure Files Filestore OCI File Storage
Los tres modelos existen en todos los proveedores principales — cambia el nombre, no el patrón de acceso.
