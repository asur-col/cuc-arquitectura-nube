Paso 1 — Crear la instancia db-hep en RDS

Objetivo: Crear la instancia relacional privada PostgreSQL con retención de backups de 7 días, base de datos pedidos y usuario admin.

Comando exacto

aws rds create-db-instance   --db-instance-identifier db-hep   --db-instance-class db.t3.micro   --engine postgres   --allocated-storage 20   --master-username admin   --master-user-password 'ClaveLab123'   --db-name pedidos   --backup-retention-period 7   --no-publicly-accessible   --tags Key=Name,Value=db-hep

Salida esperada real (capturada en estación oco-tmp-lab05)

{
    "DBInstance": {
        "DBInstanceIdentifier": "db-hep",
        "DBInstanceClass": "db.t3.micro",
        "Engine": "postgres",
        "DBInstanceStatus": "available",
        "MasterUsername": "admin",
        "DBName": "pedidos",
        "Endpoint": {
            "Address": "127.0.0.1",
            "Port": 7001
        },
        "AllocatedStorage": 20,
        "BackupRetentionPeriod": 7,
        "PubliclyAccessible": false,
        "TagList": [
            {
                "Key": "Name",
                "Value": "db-hep"
            }
        ]
    }
}

Verificación

La instancia se registra en RDS con motor PostgreSQL, almacenamiento 20 GiB, PubliclyAccessible: false y BackupRetentionPeriod: 7.

Error típico: Omitir --backup-retention-period 7 o --no-publicly-accessible.
Corrección: Revisa detenidamente los parámetros de seguridad y política de respaldos requeridos.

Criterio del verificador: Base para los criterios instancia_rds y respaldos.

Paso 2 — Esperar disponibilidad de db-hep

Objetivo: Esperar hasta que el estado del ciclo de vida de la instancia alcance available.

Comando exacto

for _ in $(seq 1 60); do
  EST=$(aws rds describe-db-instances --db-instance-identifier db-hep --query "DBInstances[0].DBInstanceStatus" --output text)
  [ "$EST" = "available" ] && break
  sleep 1
done
aws rds describe-db-instances --db-instance-identifier db-hep   --query "DBInstances[0].{ID:DBInstanceIdentifier,Status:DBInstanceStatus,Port:Endpoint.Port,Public:PubliclyAccessible,Retention:BackupRetentionPeriod}"

Salida esperada real (capturada en estación oco-tmp-lab05)

{
    "ID": "db-hep",
    "Status": "available",
    "Port": 7001,
    "Public": false,
    "Retention": 7
}

Verificación

El campo Status reporta available y se visualizan el puerto y configuración solicitados.

Error típico: Conectarse inmediatamente sin aguardar el aprovisionamiento.
Corrección: Mantén la espera activa hasta recibir el estado available.

Criterio del verificador: Cumple directamente instancia_rds y respaldos.

Paso 3 — Identificar puerto de conexión local

Objetivo: Obtener el puerto TCP publicado por floci para la instancia db-hep.

Comando exacto

PUERTO=$(aws rds describe-db-instances --db-instance-identifier db-hep --query "DBInstances[0].Endpoint.Port" --output text)
echo "Puerto Postgres: $PUERTO"

Salida esperada real (capturada en estación oco-tmp-lab05)

Puerto Postgres: 7001

Verificación

La variable almacena el número de puerto numérico asignado a la instancia.

Error típico: Intentar conectar al puerto estándar 5432.
Corrección: En el simulador floci cada instancia RDS levanta en un puerto dinámico (por ejemplo 7001, 7002).

Criterio del verificador: Canal de conectividad para poblar la base de datos.

Paso 4 — Crear la tabla de pedidos

Objetivo: Conectarse vía psql y ejecutar el DDL para la tabla pedidos.

Comando exacto

export PGPASSWORD='ClaveLab123'
psql -h 127.0.0.1 -p "$PUERTO" -U admin -d pedidos -v ON_ERROR_STOP=1 <<'SQL'
CREATE TABLE pedidos (
  id serial PRIMARY KEY,
  cliente text NOT NULL,
  total numeric(10,2) NOT NULL
);
SQL

Salida esperada real (capturada en estación oco-tmp-lab05)

CREATE TABLE

Verificación

El cliente PostgreSQL confirma la creación de la tabla con el mensaje CREATE TABLE.

Error típico: Fallo de autenticación por contraseña incorrecta.
Corrección: Exporta PGPASSWORD='ClaveLab123' coincidiendo con la clave fijada en el paso 1.

Criterio del verificador: Estructura requerida para el criterio datos.

Paso 5 — Insertar registros de producción

Objetivo: Insertar al menos dos registros válidos de prueba en la tabla pedidos.

Comando exacto

psql -h 127.0.0.1 -p "$PUERTO" -U admin -d pedidos -v ON_ERROR_STOP=1 <<'SQL'
INSERT INTO pedidos (cliente, total) VALUES ('Ana', 125000.00), ('Luis', 98000.50);
SQL

Salida esperada real (capturada en estación oco-tmp-lab05)

INSERT 0 2

Verificación

La respuesta confirma la inserción de 2 filas (INSERT 0 2).

Error típico: Insertar solo 1 fila o cometer errores sintácticos en las comillas de strings.
Corrección: El validador exige un mínimo estricto de 2 filas en pedidos.

Criterio del verificador: Condición necesaria para el criterio datos.

Paso 6 — Validar integridad de los datos

Objetivo: Consultar la tabla para confirmar que los datos residen en la base de datos primaria.

Comando exacto

psql -h 127.0.0.1 -p "$PUERTO" -U admin -d pedidos -c 'SELECT * FROM pedidos;'

Salida esperada real (capturada en estación oco-tmp-lab05)

 id | cliente |   total   
----+---------+-----------
  1 | Ana     | 125000.00
  2 | Luis    |  98000.50
(2 rows)

Verificación

La consulta lista los dos registros con sus respectivos valores y montos.

Error típico: Consultar una base de datos errónea.
Corrección: Especifica explícitamente -d pedidos.

Criterio del verificador: Valida formalmente el criterio datos.

Paso 7 — Crear snapshot manual snap-hep

Objetivo: Generar una instantánea consistente de la base de datos con identificador snap-hep.

Comando exacto

aws rds create-db-snapshot   --db-instance-identifier db-hep   --db-snapshot-identifier snap-hep

Salida esperada real (capturada en estación oco-tmp-lab05)

{
    "DBSnapshot": {
        "DBSnapshotIdentifier": "snap-hep",
        "DBInstanceIdentifier": "db-hep",
        "SnapshotCreateTime": "2026-10-30T14:06:04.626035508Z",
        "Engine": "postgres",
        "AllocatedStorage": 20,
        "Status": "available",
        "Port": 7001,
        "MasterUsername": "admin",
        "SnapshotType": "manual"
    }
}

Verificación

Se retorna el objeto JSON del snapshot con SnapshotType: manual y asociación a db-hep.

Error típico: Crear el snapshot antes de insertar los datos.
Corrección: Asegúrate de verificar los datos primero para que la copia contenga el estado íntegro.

Criterio del verificador: Base para el criterio snapshot.

Paso 8 — Validar estado de la instantánea

Objetivo: Esperar hasta que el snapshot alcance el estado available.

Comando exacto

for _ in $(seq 1 60); do
  EST=$(aws rds describe-db-snapshots --db-snapshot-identifier snap-hep --query "DBSnapshots[0].Status" --output text)
  [ "$EST" = "available" ] && break
  sleep 1
done
aws rds describe-db-snapshots --db-snapshot-identifier snap-hep   --query "DBSnapshots[0].{Snapshot:DBSnapshotIdentifier,Status:Status,Instance:DBInstanceIdentifier}"

Salida esperada real (capturada en estación oco-tmp-lab05)

{
    "Snapshot": "snap-hep",
    "Status": "available",
    "Instance": "db-hep"
}

Verificación

El snapshot se encuentra available y listo para procesos de restauración.

Error típico: Intentar restaurar un snapshot en estado creating.
Corrección: Aguarda a que el comando reporte Status: available.

Criterio del verificador: Cumple el criterio snapshot.

Paso 9 — Restaurar snapshot a db-hep-restaurada

Objetivo: Restaurar la copia de respaldo en una nueva instancia independiente denominada db-hep-restaurada.

Comando exacto

aws rds restore-db-instance-from-db-snapshot   --db-instance-identifier db-hep-restaurada   --db-snapshot-identifier snap-hep
for _ in $(seq 1 60); do
  EST=$(aws rds describe-db-instances --db-instance-identifier db-hep-restaurada --query "DBInstances[0].DBInstanceStatus" --output text)
  [ "$EST" = "available" ] && break
  sleep 1
done

Salida esperada real (capturada en estación oco-tmp-lab05)

{
    "DBInstance": {
        "DBInstanceIdentifier": "db-hep-restaurada",
        "DBInstanceClass": "db.t3.micro",
        "Engine": "postgres",
        "DBInstanceStatus": "available",
        "MasterUsername": "admin",
        "DBName": "pedidos",
        "Endpoint": {
            "Address": "127.0.0.1",
            "Port": 7002
        }
    }
}

Verificación

La nueva instancia db-hep-restaurada se levanta en un nuevo puerto (7002) en estado available.

Error típico: Restaurar con el mismo nombre que la instancia existente.
Corrección: Los nombres en RDS deben ser únicos; usa estrictamente db-hep-restaurada.

Criterio del verificador: Base del criterio restaurada.

Paso 10 — Verificar integridad y ejecutar autocontrol

Objetivo: Conectarse a la instancia restaurada, comprobar la persistencia de las 2 filas y ejecutar revisar.

Comando exacto

PUERTO2=$(aws rds describe-db-instances --db-instance-identifier db-hep-restaurada --query "DBInstances[0].Endpoint.Port" --output text)
echo "Puerto restaurada: $PUERTO2"
psql -h 127.0.0.1 -p "$PUERTO2" -U admin -d pedidos -c 'SELECT count(*) FROM pedidos;'
revisar
