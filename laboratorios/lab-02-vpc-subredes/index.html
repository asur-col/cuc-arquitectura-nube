Acerca de este laboratorio

En este laboratorio diseñarás la topología de red fundamental en la nube: una VPC 10.20.0.0/16 estructurada en dos zonas de disponibilidad (us-east-1a y us-east-1b), con aislamiento estricto de la capa privada y grupos de seguridad interrelacionados según el principio de mínimo privilegio.

Paso 1 — Crear la VPC vpc-hep

Objetivo: Crear la VPC principal con bloque CIDR 10.20.0.0/16 y asignarle la etiqueta Name=vpc-hep.

Comando exacto

VPC=$(aws ec2 create-vpc --cidr-block 10.20.0.0/16   --tag-specifications 'ResourceType=vpc,Tags=[{Key=Name,Value=vpc-hep}]'   --query 'Vpc.VpcId' --output text)
echo "VPC_ID: $VPC"

Salida esperada real (capturada en estación oco-tmp-lab02)

VPC_ID: vpc-00e37ea5

Verificación

Se obtiene un identificador único de VPC (ej. vpc-00e37ea5).

Error típico y corrección

Error: CIDR erróneo (p. ej. 10.0.0.0/16). Corrección: Debe ser estrictamente 10.20.0.0/16.

Criterio del verificador: Base obligatoria para vpc_subredes.

Paso 2 — Crear subredes públicas

Objetivo: Crear dos subredes para la capa pública: 10.20.1.0/24 en us-east-1a y 10.20.2.0/24 en us-east-1b.

Comando exacto

SUBA=$(aws ec2 create-subnet --vpc-id "$VPC" --cidr-block 10.20.1.0/24   --availability-zone us-east-1a   --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=sub-pub-a}]'   --query 'Subnet.SubnetId' --output text)
SUBB=$(aws ec2 create-subnet --vpc-id "$VPC" --cidr-block 10.20.2.0/24   --availability-zone us-east-1b   --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=sub-pub-b}]'   --query 'Subnet.SubnetId' --output text)
echo "PUBLIC_SUBNETS: $SUBA $SUBB"

Salida esperada real (capturada en estación oco-tmp-lab02)

PUBLIC_SUBNETS: subnet-9b05504c subnet-1bbaed85

Verificación

Ambas subredes deben quedar registradas en distintas zonas de disponibilidad para asegurar alta disponibilidad.

Error típico y corrección

Error: Asignar ambas subredes a la misma zona de disponibilidad. Corrección: Especifica explícitamente us-east-1a y us-east-1b.

Criterio del verificador: Parte pública de vpc_subredes.

Paso 3 — Crear subredes privadas

Objetivo: Crear dos subredes para la capa privada: 10.20.11.0/24 en us-east-1a y 10.20.12.0/24 en us-east-1b.

Comando exacto

SUBPA=$(aws ec2 create-subnet --vpc-id "$VPC" --cidr-block 10.20.11.0/24   --availability-zone us-east-1a   --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=sub-priv-a}]'   --query 'Subnet.SubnetId' --output text)
SUBPB=$(aws ec2 create-subnet --vpc-id "$VPC" --cidr-block 10.20.12.0/24   --availability-zone us-east-1b   --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=sub-priv-b}]'   --query 'Subnet.SubnetId' --output text)
echo "PRIVATE_SUBNETS: $SUBPA $SUBPB"

Salida esperada real (capturada en estación oco-tmp-lab02)

PRIVATE_SUBNETS: subnet-e1023b30 subnet-7f54e543

Verificación

Las subredes privadas no deben tener activada la asignación automática de IP pública (MapPublicIpOnLaunch=false).

Error típico y corrección

Error: Confundir los bloques CIDR privados con los públicos. Corrección: Usa exactamente 10.20.11.0/24 y 10.20.12.0/24.

Criterio del verificador: Completa el criterio vpc_subredes (1,0 pt) y sienta la base de privadas_sin_salida.

Paso 4 — Crear y asociar Internet Gateway

Objetivo: Crear el Internet Gateway etiquetado como igw-hep y adjuntarlo a la VPC creada.

Comando exacto

IGW=$(aws ec2 create-internet-gateway   --tag-specifications 'ResourceType=internet-gateway,Tags=[{Key=Name,Value=igw-hep}]'   --query 'InternetGateway.InternetGatewayId' --output text)
echo "IGW_ID: $IGW"
aws ec2 attach-internet-gateway --vpc-id "$VPC" --internet-gateway-id "$IGW"

Salida esperada real (capturada en estación oco-tmp-lab02)

IGW_ID: igw-2a429871

Verificación

attach-internet-gateway se ejecuta con éxito y finaliza sin errores.

Error típico y corrección

Error: Olvidar ejecutar el comando attach-internet-gateway. Corrección: El IGW debe estar vinculado a la VPC.

Criterio del verificador: Requisito para salida_publica.

Paso 5 — Crear tabla de rutas pública

Objetivo: Crear una tabla de enrutamiento personalizada con la etiqueta Name=rt-publica dentro de la VPC.

Comando exacto

RT=$(aws ec2 create-route-table --vpc-id "$VPC"   --tag-specifications 'ResourceType=route-table,Tags=[{Key=Name,Value=rt-publica}]'   --query 'RouteTable.RouteTableId' --output text)
echo "RT_ID: $RT"

Salida esperada real (capturada en estación oco-tmp-lab02)

RT_ID: rtb-dc3a30d3

Verificación

Se obtiene un identificador único de tabla de rutas (ej. rtb-dc3a30d3).

Error típico y corrección

Error: Olvidar la etiqueta Name=rt-publica. Corrección: El verificador busca la tabla por este tag exacto.

Criterio del verificador: Requisito para salida_publica.

Paso 6 — Agregar ruta predeterminada hacia el Internet Gateway

Objetivo: Configurar en rt-publica una ruta que dirija todo el tráfico saliente (0.0.0.0/0) hacia el IGW.

Comando exacto

aws ec2 create-route --route-table-id "$RT"   --destination-cidr-block 0.0.0.0/0 --gateway-id "$IGW"

Salida esperada real (capturada en estación oco-tmp-lab02)

{
    "Return": true
}

Verificación

La respuesta JSON devuelve "Return": true.

Error típico y corrección

Error: GatewayNotAttached. Corrección: Verifica que el paso 4 se haya completado correctamente.

Criterio del verificador: Elemento clave del criterio salida_publica.

Paso 7 — Asociar subredes públicas a la tabla de rutas

Objetivo: Asociar explícitamente las dos subredes públicas a rt-publica, dejando las privadas en la tabla principal.

Comando exacto

aws ec2 associate-route-table --subnet-id "$SUBA" --route-table-id "$RT"
aws ec2 associate-route-table --subnet-id "$SUBB" --route-table-id "$RT"

Salida esperada real (capturada en estación oco-tmp-lab02)

{
    "AssociationId": "rtbassoc-f1422438",
    "AssociationState": {
        "State": "associated"
    }
}
{
    "AssociationId": "rtbassoc-96629849",
    "AssociationState": {
        "State": "associated"
    }
}

Verificación

Cada asociación produce un AssociationId con estado associated.

Error típico y corrección

Error: Asociar por equivocación una subred privada a rt-publica. Corrección: Solo asocia sub-pub-a y sub-pub-b.

Criterio del verificador: Completa el criterio salida_publica (1,0 pt).

Paso 8 — Crear grupo de seguridad sg-web

Paso 9 — Crear grupo de seguridad sg-db

Objetivo: Crear el grupo sg-db permitiendo el puerto 5432 exclusivamente con origen referenciado en sg-web.

Comando exacto

SG_DB=$(aws ec2 create-security-group --group-name sg-db   --description "base de datos" --vpc-id "$VPC" --query GroupId --output text)
echo "SG_DB_ID: $SG_DB"
aws ec2 authorize-security-group-ingress --group-id "$SG_DB" --ip-permissions   "[{"IpProtocol":"tcp","FromPort":5432,"ToPort":5432,
     "UserIdGroupPairs":[{"GroupId":"$SG_WEB","Description":"desde web"}]}]"
