Acerca de este laboratorio

En este laboratorio aplicarás los principios fundamentales de gobernanza y seguridad de AWS IAM: políticas de asunción de rol (Trust Relationships) limitadas a servicios específicos, políticas de permisos basadas en ARN sin comodines (least privilege), perfiles de instancia para cómputo y denegaciones explícitas de alta prioridad.

Paso 1 — Redactar la política de confianza para EC2

Objetivo: Diseñar el documento JSON que permite exclusivamente al servicio ec2.amazonaws.com asumir el rol vía sts:AssumeRole.

Comando exacto

mkdir -p /workspace/lab-03 && cd /workspace/lab-03
cat > confianza.json <<'JSON'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {"Service": "ec2.amazonaws.com"},
      "Action": "sts:AssumeRole"
    }
  ]
}
JSON
cat confianza.json

Salida esperada real (capturada en estación oco-tmp-lab03)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {"Service": "ec2.amazonaws.com"},
      "Action": "sts:AssumeRole"
    }
  ]
}

Verificación

El JSON debe ser válido y contener estrictamente el servicio ec2.amazonaws.com en Principal.

Error típico y corrección

Error: Usar "Principal": "*". Corrección: Permitir a cualquiera asumir el rol es una vulnerabilidad crítica rechazada por el verificador.

Criterio del verificador: Base para rol_confianza.

Paso 4 — Redactar la política de permisos de solo lectura

Objetivo: Declarar permisos mínimos: GetObject para los objetos (/*) y ListBucket para la raíz del bucket.

Comando exacto

cat > politica-leer-sitio.json <<'JSON'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::sitio-hep/*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::sitio-hep"
    }
  ]
}
JSON
cat politica-leer-sitio.json

Salida esperada real (capturada en estación oco-tmp-lab03)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::sitio-hep/*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::sitio-hep"
    }
  ]
}

Verificación

Comprueba rigurosamente la asociación de GetObject con /* y ListBucket con el ARN directo del bucket.

Error típico y corrección

Error: Invertir los recursos (poner ListBucket sobre /* o GetObject sobre el bucket). Corrección: En S3 las operaciones sobre objetos requieren el sufijo comodín de clave.

Criterio del verificador: Base para politica_bucket.

Paso 6 — Auditar ausencia estricta de comodines

Objetivo: Verificar con get-role-policy que no se incluyan acciones ni recursos abiertos (*).

Comando exacto

aws iam get-role-policy   --role-name rol-app-hep   --policy-name politica-leer-sitio   --query 'PolicyDocument' --output json

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3:GetObject"
            ],
            "Resource": "arn:aws:s3:::sitio-hep/*"
        },
        {

            "Action": [
                "s3:ListBucket"

No existen acciones como s3:* ni recursos como *.

Criterio del verificador: Satisface completamente el criterio sin_comodines (1,0 pt).

Paso 8 — Asociar el rol al instance profile

Comando exacto

Salida esperada real (capturada en estación oco-tmp-lab03)

Error típico y corrección

Error: Omitir add-role-to-instance-profile. Corrección: Un perfil vacío no otorga credenciales a una máquina virtual.

Criterio del verificador: Satisface completamente el criterio instance_profile (1,0 pt).

Paso 9 — Crear usuario auditor y aplicar política con Deny explícito

Objetivo: Crear el usuario auditor-hep permitiendo listar buckets pero denegando explícitamente DeleteObject.

Comando exacto

aws iam create-user --user-name auditor-hep
cat > politica-auditor.json <<'JSON'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListAllMyBuckets"],
      "Resource": "*"
    },
    {
      "Effect": "Deny",
      "Action": ["s3:DeleteObject"],
      "Resource": "arn:aws:s3:::sitio-hep/*"
    }
  ]
}
JSON
aws iam put-user-policy   --user-name auditor-hep   --policy-name politica-auditor   --policy-document file://politica-auditor.json

Salida esperada real (capturada en estación oco-tmp-lab03)

{
    "User": {
        "Path": "/",
        "UserName": "auditor-hep",
        "UserId": "AIDACQCBOIO9H9HZK8HD",
        "Arn": "arn:aws:iam::000000000000:user/auditor-hep",
        "CreateDate": "2026-10-30T13:47:47.345Z"
    }
}

Verificación

El usuario cuenta con la política inline que establece la regla de denegación explícita.

Error típico y corrección

Error: Omitir la regla Deny o usar otra acción. Corrección: La acción debe ser estrictamente s3:DeleteObject.

Criterio del verificador: Satisface completamente el criterio usuario_auditor (1,0 pt).
