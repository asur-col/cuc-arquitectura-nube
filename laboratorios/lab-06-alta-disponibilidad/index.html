Paso 1 — Crear el stack CloudFormation hep-ha

Objetivo: Desplegar la infraestructura base (VPC multizona, subredes, SG, ALB y Target Group) mediante la plantilla provista en /workspace/lab-06/plantilla-ha.json.

Comando exacto

PLANTILLA="/workspace/lab-06/plantilla-ha.json"
aws cloudformation create-stack   --stack-name hep-ha   --template-body "file://$PLANTILLA"

Salida esperada real (capturada en estación oco-tmp-lab06)

{
    "StackId": "arn:aws:cloudformation:us-east-1:000000000000:stack/hep-ha/c490bb3e-d431-4c9e-a666-0c7ff271f79a"
}

Verificación

CloudFormation retorna el identificador ARN del stack confirmando la recepción de la plantilla.

Error típico: Ruta errónea en --template-body.
Corrección: Usa el prefijo file:// apuntando a /workspace/lab-06/plantilla-ha.json.

Criterio del verificador: Base obligatoria para el criterio stack.

Paso 2 — Esperar estado CREATE_COMPLETE

Objetivo: Monitorizar el aprovisionamiento del stack hasta alcanzar el estado CREATE_COMPLETE.

for _ in $(seq 1 60); do

  sleep 1
done

    "StackName": "hep-ha",
    "Status": "CREATE_COMPLETE"
}

Verificación

El stack confirma Status: CREATE_COMPLETE habiendo aprovisionado todos los recursos declarativos.

Error típico: Estado en CREATE_FAILED.

Criterio del verificador: Valida directamente el criterio stack.

Paso 3 — Descubrir recursos de red y balanceo

Objetivo: Extraer el identificador del grupo de seguridad, las subredes multizona (sub-ha-a, sub-ha-b) y el ARN de tg-hep creados por CloudFormation.

Comando exacto

SG=$(aws cloudformation describe-stack-resource --stack-name hep-ha   --logical-resource-id SG --query 'StackResourceDetail.PhysicalResourceId' --output text)

SUBB=$(aws ec2 describe-subnets --filters Name=tag:Name,Values=sub-ha-b   --query 'Subnets[0].SubnetId' --output text)
TGARN=$(aws elbv2 describe-target-groups --names tg-hep   --query 'TargetGroups[0].TargetGroupArn' --output text)

Verificación

Se descubren IDs válidos para el SG, ambas subredes en diferentes zonas de disponibilidad y el target group.

Paso 7 — Crear Auto Scaling Group asg-hep

Objetivo: Crear el grupo de autoescalado asg-hep con capacidad 2/4/2, multizona en $SUBA,$SUBB y vinculado a tg-hep.

Comando exacto

aws autoscaling create-auto-scaling-group --auto-scaling-group-name asg-hep   --launch-template LaunchTemplateId="$LTID",Version='$Latest'   --min-size 2 --max-size 4 --desired-capacity 2   --vpc-zone-identifier "$SUBA,$SUBB"   --target-group-arns "$TGARN"   --tags Key=Name,Value=asg-hep,PropagateAtLaunch=true

Salida esperada real (capturada en estación oco-tmp-lab06)

(Comando ejecutado exitosamente con código de salida 0)

Verificación

La llamada retorna código 0 y el servicio inicia el aprovisionamiento de las instancias.

Error típico: Configurar capacidades diferentes a min: 2, max: 4, desired: 2.
Corrección: Respeta exactamente las cifras 2/4/2 exigidas por la rúbrica.

Criterio del verificador: Base para el criterio asg.

Paso 9 — Comprobar servicio HTTP en instancias

Objetivo: Constatar que ambas instancias del ASG responden código 200 y entregan la marca del sitio.

Comando exacto

OK=0
for _ in $(seq 1 60); do
  IDS=$(aws autoscaling describe-auto-scaling-groups --auto-scaling-group-names asg-hep     --query 'AutoScalingGroups[0].Instances[].InstanceId' --output text)
  OK=0
  for IID in $IDS; do
    EST=$(aws ec2 describe-instances --instance-ids "$IID" --query 'Reservations[0].Instances[0].State.Name' --output text)
    [ "$EST" = "running" ] || continue
    PORT=$(docker ps --format '{{.Names}} {{.Ports}}' | sed -n "s/^floci-aws-ec2-fwd-$IID-80 .*0\.0\.0\.0:\([0-9]*\)->80.*//p" | head -1)
    [ -n "$PORT" ] || continue
    if curl -sf "http://127.0.0.1:$PORT/" | grep -q 'CaribeMart HEP'; then
      OK=$((OK + 1))
    fi
  done
  [ "$OK" -ge 2 ] && break
  sleep 1
done
echo "Instancias sirviendo HTTP: $OK"

Salida esperada real (capturada en estación oco-tmp-lab06)

Instancias sirviendo HTTP: 2

Verificación

El bucle confirma que ambas instancias están operativas y respondiendo satisfactoriamente.

Error típico: Los procesos httpd no levantaron a tiempo.
Corrección: Asegúrate de que el user-data contenga httpd -f -p 80 -h /www.

Criterio del verificador: Condición necesaria para instancias_sirven.
