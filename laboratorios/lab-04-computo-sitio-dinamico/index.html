Paso 1 — Crear la VPC vpc-app-hep

Objetivo: Crear la VPC base con bloque CIDR 10.30.0.0/16 y etiqueta identificadora vpc-app-hep.

Paso 2 — Crear la subred sub-app-hep

Objetivo: Crear una subred 10.30.1.0/24 en la zona us-east-1a vinculada a la VPC vpc-app-hep.

aws ec2 create-subnet --vpc-id "$VPC" --cidr-block 10.30.1.0/24   --availability-zone us-east-1a   --tag-specifications 'ResourceType=subnet,Tags=[{Key=Name,Value=sub-app-hep}]'

Paso 3 — Crear el Security Group sg-app

Objetivo: Crear el grupo de seguridad sg-app en la VPC para el servidor web.

Comando exacto

aws ec2 create-security-group --group-name sg-app   --description "web del laboratorio" --vpc-id "$VPC"

Salida esperada real (capturada en estación oco-tmp-lab04)

{
    "GroupId": "sg-2e2586ae98f81db91"
}

Verificación

El comando retorna un identificador de grupo con prefijo sg-.

Error típico: Crear el grupo en la VPC por defecto.
Corrección: Asegúrate de pasar siempre --vpc-id "$VPC".

Criterio del verificador: Identificador obligatorio para el criterio sg_app.

Paso 4 — Autorizar tráfico HTTP en sg-app

Objetivo: Habilitar ingreso TCP en el puerto 80 desde cualquier origen (0.0.0.0/0) sin permitir puertos adicionales.

Comando exacto

SG=$(aws ec2 describe-security-groups --filters Name=group-name,Values=sg-app --query "SecurityGroups[0].GroupId" --output text)
aws ec2 authorize-security-group-ingress --group-id "$SG"   --protocol tcp --port 80 --cidr 0.0.0.0/0
aws ec2 describe-security-groups --group-ids "$SG" --query "SecurityGroups[0].IpPermissions"

Salida esperada real (capturada en estación oco-tmp-lab04)

[
    {
        "FromPort": 80,
        "IpProtocol": "tcp",
        "IpRanges": [
            {
                "CidrIp": "0.0.0.0/0"
            }
        ],
        "Ipv6Ranges": [],
        "PrefixListIds": [],
        "ToPort": 80,
        "UserIdGroupPairs": []
    }
]

Verificación

El arreglo IpPermissions contiene exactamente una regla TCP en el puerto 80 desde 0.0.0.0/0.

Error típico: Abrir puertos adicionales como SSH (22) o HTTPS (443).
Corrección: El evaluador de mínimo privilegio exige estrictamente solo el puerto 80.

Criterio del verificador: Cumple directamente el criterio sg_app.

Paso 6 — Lanzar instancia web-hep

Objetivo: Instanciar la máquina virtual con AMI ami-hep-app, tipo t3.micro, subred sub-app-hep, grupo sg-app y etiqueta web-hep.

Comando exacto

SUB=$(aws ec2 describe-subnets --filters Name=tag:Name,Values=sub-app-hep --query "Subnets[0].SubnetId" --output text)
aws ec2 run-instances   --image-id ami-hep-app --instance-type t3.micro   --subnet-id "$SUB" --security-group-ids "$SG"   --user-data file:///tmp/user-data.sh   --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=web-hep}]'

Paso 7 — Verificar estado running de la instancia

Objetivo: Esperar la inicialización completa hasta que el ciclo de vida alcance running.

Comando exacto

IID=$(aws ec2 describe-instances --filters Name=tag:Name,Values=web-hep --query "Reservations[0].Instances[0].InstanceId" --output text)
for _ in $(seq 1 40); do
  EST=$(aws ec2 describe-instances --instance-ids "$IID" --query "Reservations[0].Instances[0].State.Name" --output text)
  [ "$EST" = "running" ] && break
  sleep 1
done
aws ec2 describe-instances --instance-ids "$IID"   --query "Reservations[0].Instances[0].{InstanceId:InstanceId,State:State.Name,ImageId:ImageId,InstanceType:InstanceType}"

Salida esperada real (capturada en estación oco-tmp-lab04)

{
    "InstanceId": "i-87a1dcdd581335865",
    "State": "running",
    "ImageId": "ami-hep-app",
    "InstanceType": "t3.micro"
}

Verificación

La consulta confirma State: running con ami-hep-app y t3.micro.

Error típico: Ejecutar los pasos siguientes mientras la instancia sigue en pending.
Corrección: Espera en bucle hasta que la transición a running concluya.

Criterio del verificador: Valida el criterio instancia.

Paso 8 — Reservar IP elástica eip-hep

Objetivo: Solicitar una dirección IP pública estática en el dominio VPC con etiqueta eip-hep.

Comando exacto

aws ec2 allocate-address --domain vpc   --tag-specifications 'ResourceType=elastic-ip,Tags=[{Key=Name,Value=eip-hep}]'

Salida esperada real (capturada en estación oco-tmp-lab04)

{
    "PublicIp": "54.9.228.242",
    "AllocationId": "eipalloc-f5186a3a49a6c779a",
    "Domain": "vpc"
}

Verificación

Se genera un recurso con AllocationId (prefijo eipalloc-) y dominio vpc.

Error típico: Olvidar el parámetro --domain vpc.
Corrección: Es mandatorio especificar --domain vpc para direcciones de VPC.

Criterio del verificador: Base para el criterio eip.

Paso 9 — Asociar IP elástica a web-hep

Objetivo: Enlazar la dirección reservada a la instancia web-hep en ejecución.

Comando exacto

ALLOC=$(aws ec2 describe-addresses --filters Name=tag:Name,Values=eip-hep --query "Addresses[0].AllocationId" --output text)
aws ec2 associate-address --instance-id "$IID" --allocation-id "$ALLOC"
aws ec2 describe-addresses --filters Name=tag:Name,Values=eip-hep   --query "Addresses[].{IP:PublicIp,Instancia:InstanceId,AllocationId:AllocationId}"

Salida esperada real (capturada en estación oco-tmp-lab04)

[
    {
        "IP": "10.30.1.10",
        "Instancia": "i-87a1dcdd581335865",
        "AllocationId": "eipalloc-f5186a3a49a6c779a"
    }
]

Verificación

El listado de direcciones refleja el enlace activo vinculando AllocationId con el InstanceId de web-hep.

Error típico: Indicar un InstanceId inexistente o terminado.
Corrección: Revisa el ID con aws ec2 describe-instances.

Criterio del verificador: Cumple el criterio eip.

Paso 10 — Validar servicio HTTP y autocontrol

Objetivo: Descubrir el puerto publicado por floci, verificar la respuesta HTTP con CaribeMart HEP y correr revisar.

Comando exacto

PORT=""
for _ in $(seq 1 40); do
  PORT=$(docker ps --format "{{.Names}} {{.Ports}}" | sed -n "s/^floci-aws-ec2-fwd-$IID-80 .*0\.0\.0\.0:\([0-9]*\)->80.*//p" | head -1)
  if [ -n "$PORT" ] && curl -sf "http://127.0.0.1:$PORT/" | grep -q "CaribeMart HEP"; then break; fi
  sleep 1
done
echo "Puerto descubierto: $PORT"
curl -i "http://127.0.0.1:$PORT/"
revisar
