Acerca de este laboratorio

En este laboratorio vas a gestionar almacenamiento de objetos compatible con Amazon S3 utilizando la nube local floci. Implementarás un bucket con versionado activo, metadatos MIME rigurosos y páginas web comprobables por HTTP.

Paso 1 — Crear el bucket S3

Objetivo: Crear el bucket sitio-hep en la región por defecto us-east-1.

Comando exacto

aws s3api create-bucket --bucket sitio-hep

Salida esperada real (capturada en estación oco-tmp-lab01)

{
    "Location": "/sitio-hep"
}

Verificación

Confirma que el comando finaliza con código de salida 0 y retorna el identificador del recurso en JSON.

Error típico y corrección

Error: BucketAlreadyExists o BucketAlreadyOwnedByYou. Corrección: El bucket ya fue creado; continúa con el siguiente paso o verifica su estado.

Criterio del verificador: Base para el criterio bucket_creado.

Paso 2 — Verificar existencia y región del bucket

Objetivo: Confirmar mediante head-bucket y get-bucket-location que el bucket existe y está en us-east-1.

Comando exacto

aws s3api head-bucket --bucket sitio-hep
aws s3api get-bucket-location --bucket sitio-hep

Salida esperada real (capturada en estación oco-tmp-lab01)

{
    "BucketRegion": "us-east-1"
}
{
    "LocationConstraint": null
}

Verificación

La salida LocationConstraint: null en AWS S3 indica explícitamente que el bucket pertenece a us-east-1.

Error típico y corrección

Error: 404 Not Found. Corrección: Revisa que no haya errores tipográficos en el nombre sitio-hep.

Criterio del verificador: Satisface completamente el criterio bucket_creado (1,0 pt).

Paso 3 — Habilitar versionado en el bucket

Objetivo: Activar el seguimiento de versiones para conservar el historial de cambios de cada objeto subido.

Comando exacto

aws s3api put-bucket-versioning   --bucket sitio-hep   --versioning-configuration Status=Enabled

Salida esperada real (capturada en estación oco-tmp-lab01)

(Comando ejecutado silenciosamente con código de retorno 0)

Verificación

El comando no emite salida de texto cuando tiene éxito.

Error típico y corrección

Error: MalformedXML. Corrección: Asegúrate de que el parámetro Status=Enabled esté bien escrito y sin espacios.

Criterio del verificador: Requisito indispensable para el criterio versionado.

Paso 4 — Comprobar estado del versionado

Objetivo: Consultar la configuración activa del bucket y asegurar que el estado sea Enabled.

Comando exacto

aws s3api get-bucket-versioning --bucket sitio-hep

Salida esperada real (capturada en estación oco-tmp-lab01)

{
    "Status": "Enabled"
}

Verificación

El campo Status del objeto JSON devuelto debe ser exactamente "Enabled".

Error típico y corrección

Error: Respuesta vacía {}. Corrección: El versionado aún no está activo; vuelve a ejecutar put-bucket-versioning.

Criterio del verificador: Valida el estado activo de versionado en versionado.

Paso 5 — Publicar archivos iniciales del sitio con Content-Type

Objetivo: Subir index.html, error.html y estilo.css especificando explícitamente el encabezado Content-Type.

Comando exacto

cd /workspace/sitio
aws s3api put-object --bucket sitio-hep --key index.html   --body index.html --content-type "text/html; charset=utf-8"
aws s3api put-object --bucket sitio-hep --key error.html   --body error.html --content-type "text/html; charset=utf-8"
aws s3api put-object --bucket sitio-hep --key estilo.css   --body estilo.css --content-type "text/css; charset=utf-8"

Salida esperada real (capturada en estación oco-tmp-lab01)

{
    "ETag": ""3d9ef5d67a48c8f7b722b248a60c6287"",
    "VersionId": "a49d642e-50fe-47ea-91bd-81c3f2a9a39c"
}
{
    "ETag": ""ec7c9843e36c1da3877df8d5ddc3a84a"",
    "VersionId": "40e4e61f-b3ef-4685-9618-7da555a0aa4c"
}
{
    "ETag": ""27f23a460e3874a68a835faeb6d002db"",
    "VersionId": "6038e83a-1ede-4c09-b45b-81b0f1c86120"
}

Verificación

Cada subida genera un VersionId único generado por el motor de S3.

Error típico y corrección

Error: NoSuchFile al leer el cuerpo. Corrección: Confirma que estás dentro del directorio /workspace/sitio.

Criterio del verificador: Base para el cumplimiento de objetos.

Paso 7 — Crear y subir la segunda versión de index.html

Objetivo: Modificar el archivo localmente y subirlo de nuevo para generar un nuevo registro histórico en S3.

Comando exacto

sed -i 's/Versión del sitio: <strong>borrador<\/strong>/Versión del sitio: <strong>1.0 — publicada<\/strong>/g' /workspace/sitio/index.html
aws s3api put-object --bucket sitio-hep --key index.html   --body /workspace/sitio/index.html --content-type "text/html; charset=utf-8"

Salida esperada real (capturada en estación oco-tmp-lab01)

{
    "ETag": ""1d080ba0f1033e617019299fcdb83e75"",
    "VersionId": "8663cb6b-b8d9-4aad-918e-a80b654c3e48"
}

Verificación

El nuevo VersionId debe ser distinto al obtenido en el paso 5.

Error típico y corrección

Error: Reemplazar el archivo sin cambios. Corrección: Comprueba con git diff o grep que la cadena cambió.

Criterio del verificador: Genera la segunda versión necesaria para versionado.

Paso 9 — Configurar hosting de sitio web

Objetivo: Establecer la configuración de sitio web estático asociando IndexDocument y ErrorDocument.

Comando exacto

aws s3api put-bucket-website --bucket sitio-hep   --website-configuration '{"IndexDocument":{"Suffix":"index.html"},"ErrorDocument":{"Key":"error.html"}}'
aws s3api get-bucket-website --bucket sitio-hep

Salida esperada real (capturada en estación oco-tmp-lab01)

{
    "IndexDocument": {
        "Suffix": "index.html"
    },
    "ErrorDocument": {
        "Key": "error.html"
    }
}

Verificación

El comando get-bucket-website devuelve la configuración exacta registrada en el bucket.

Error típico y corrección

Error: JSON malformado. Corrección: Respeta las comillas dobles en las claves de la configuración JSON.

Criterio del verificador: Estructura la resolución web del bucket.
